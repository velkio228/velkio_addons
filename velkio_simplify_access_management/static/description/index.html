Overview

Access rights, without the headache

Setting up who-sees-what in Odoo normally means juggling groups, writing record rules, overriding views and hiding menus one by one. Simplify Access Management replaces all of that with a single record — the Access Studio — where you pick the users and then tick exactly what they may see and do.

Rules can be activated or deactivated without being deleted, they respect multi-company boundaries, and each tab carries in-form guidance describing every option.

🏗 One record per audience
Bundle menus, models, fields, buttons, filters and record domains into one reusable rule and assign it to the users who need it.
🛠 UI-only or fully enforced
Hide buttons for a back-office user, or use Domain Access for a real security rule that also blocks imports, automations, the API and POS.
👥 Read-only user, one click
Turn any non-admin user read-only across the entire system with a single switch.
⚡ Cached & fast
Lookups are cached per user and cleared automatically whenever a rule changes.
The 8 Tabs

Everything you can control

🔑
Hide Menu
Hide any application menu or sub-menu. Hiding a parent hides everything under it and blocks its screen.
📂
Model Access
Per model: hide reports, server actions, whole views (List, Kanban, Pivot, Graph…) and the Create / Edit / Delete / Archive / Duplicate / Import / Export / Spreadsheet buttons.
✎
Field Access
Make any field invisible, read-only or required, and remove the arrow that opens a linked record.
🛡
Domain Access
Enforced rights: allow / block Read, Create, Update, Delete, and restrict visible records with a filter. Applies everywhere — UI, imports, API, POS.
📌
Button / Tab Access
Hide individual action & object buttons (including smart buttons), form notebook tabs, and Kanban action links.
🔍
Hide Filter / Group By
Remove specific predefined filters and Group-By options from the search box of any model.
💬
Chatter
Hide the whole chatter panel per model, or keep it and remove just Send Message / Log Note / Schedule Activity.
🌐
Global
Apply a rule to every model at once — chatter, import / export, login, developer mode, relational create / edit.
📜
In-form Help
Each tab shows an info panel describing every column and when to use it.
Global Switches

One tick, every model

ChatterHide the chatter everywhere, or keep it and drop just the Send Message / Log Note / Schedule Activity buttons.
Import & ExportHide Import, Export, Insert-in-Spreadsheet and “Add Property” on every model.
Disable LoginInstantly block the selected user(s) from signing in.
Disable Developer ModeForce developer mode off for the user, even from the URL.
Disable Relational Create/Edit
NEW		On every Many2one / Many2many field of every screen, remove “Create”, “Create & edit…” and quick-create, and hide the arrow that opens the linked record. Users can still pick from existing records — they just can’t create or edit customers, products, tags, etc. inline. No per-field setup.
Workflow

How a rule is built

1
Open Access Studio and create a rule
Give it a name; it is active by default.
2
Pick the users and companies
The rule applies only to these users, and only inside these companies.
3
Fill the tabs
Add the menus, models, fields, buttons, filters or record domains to restrict. Each tab explains its columns.
4
Save
Affected users see the change on their next page reload. Deactivate the rule any time to lift it instantly.
Setup

Install in two minutes

1
Add the module
Copy it into your addons path, update the app list, then install Simplify Access Management from Apps. It depends only on web — the advanced domain widget is bundled in.
2
Grant the manager group
Give your administrators the Access Management group so they can see the Access Studio app.
3
Create your first rule
Open Access Studio, add a rule, choose the users, and start restricting.
